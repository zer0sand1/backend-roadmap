Backend Engineering Roadmap

15 projects designed to take you from HTTP fundamentals to production-ready microservices. Every project builds on the last, introducing one new first-principle concept at a time. Complete these and you will be comfortable with 90% of what startups ask for at the fresher level.

Python + TypeScript Fresher / Startup-ready ~4–6 months First-principles focus
01
Custom HTTP Server from Scratch
Understand the protocol before using the framework
PythonsocketHTTP/1.1TCP

Build a bare-bones HTTP/1.1 server using only Python's socket library. No frameworks, no web libraries. Your server should parse raw HTTP requests, route them to handlers, and return proper responses. This is the foundation everything else sits on.

Read Before

  • How TCP works (3-way handshake, sockets)
  • HTTP/1.1 message format (request line, headers, body)
  • HTTP methods: GET, POST, PUT, DELETE
  • Status codes (200, 201, 400, 404, 500)
  • RFC 7230 — HTTP/1.1 Message Syntax

New Skills

  • Socket programming and event loops
  • Parsing raw TCP data into HTTP messages
  • Concurrency with threads vs async
  • Writing a basic router from scratch
  • Debugging network protocols (curl, telnet)

Verification Goals

  • curl -v http://localhost:8080/ returns a valid HTTP response with headers
  • Your server handles GET /, POST /data, 404 for unknown routes
  • Concurrent connections work (open 3 tabs simultaneously)
  • Returns proper Content-Type and Content-Length headers
  • Can serve a static HTML file from disk

Verification Goals

  • /docs shows interactive Swagger UI
  • You can explain what each REST constraint means in practice

New Skills

  • SQLAlchemy model definitions & relationships
  • Writing and running Alembic migrations

  • Base62 encoding for short codes

Verification Goals

  • POST /shorten returns a short URL; visiting it redirects
  • Database persists across server restarts
  • Alembic can upgrade/downgrade schema
  • Index on short_code makes lookups fast (EXPLAIN ANALYZE)
  • Same long URL can be shortened multiple times (or deduped)

E-commerce Order Service
Transactions, inventory contention, idempotency, saga pattern
PythonFastAPIPostgreSQLSQLAlchemy

Build an order management system with products, inventory, carts, and orders. The core challenge: handle concurrent purchases correctly. Implement optimistic and pessimistic locking. Use database transactions for atomicity. Add idempotency keys to prevent double charges.

Read Before

  • ACID properties (Atomicity, Consistency, Isolation, Durability)
  • Transaction isolation levels (READ COMMITTED, SERIALIZABLE)
  • Pessimistic vs optimistic locking
  • Idempotency keys — why payments need them
  • Saga pattern for distributed transactions

New Skills

  • SQLAlchemy session management & transactions
  • SELECT ... FOR UPDATE (pessimistic lock)
  • Optimistic locking with version columns
  • Idempotency key creation and dedup
  • Compensating transactions (saga pattern)

Verification Goals

  • Two users buying the last item — one succeeds, one gets 409
  • Same idempotency key returns same result, doesn't double-order
  • Inventory count is always accurate after concurrent purchases
  • Order creation is atomic (items + payment + inventory all or nothing)
  • Partial failure triggers compensating actions (rollback)

New Skills

  • Declaring exchanges, queues, bindings

How to Approach This Roadmap

1. Build, Don't Copy

  • Type every line yourself
  • Read error messages carefully
  • Use debuggers, don't guess

2. Read Deeply When Stuck

  • Search for "why" not "how"
  • Read RFCs, source code, blog posts
  • Understand the underlying principle

3. Verify Every Goal

  • Each project has specific verification goals
  • Don't move on until you pass them all
  • Write automated tests to prove it works

4. Portfolio Ready

  • Push every project to GitHub
  • Write a good README for each
  • Be ready to explain your design choices
