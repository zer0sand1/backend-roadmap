# Product Context: Backend Engineering Roadmap

## Users
- Backend engineering students/freshers learning from first principles
- Self-taught developers building a portfolio for startup interviews
- Recruiters evaluating proof-of-work

## Product Purpose
A sequential reference website of 18 backend engineering projects. Each project page teaches one first-principle concept. Users visit repeatedly while building projects over 5-7 months.

## Register
Product (design serves information, not the product itself)

## Scene
A developer studying at their desk, often at night, referencing the next project to build. The site should feel calm, focused, and trustworthy — like a well-designed technical book or documentation site. Not flashy. Not SaaS-corporate.

## Tone
- Calm, focused, precise
- Understated confidence
- Editorial / craft-oriented
- No hype, no emojis in design, no marketing speak

## Anti-references
- SaaS landing pages with big metrics and gradient buttons
- Documentation sites that look like every other docs site (readthedocs, docusaurus default)
- Dark mode that tries too hard to be "cyberpunk" or "hacker"
- Card grids with identical icon-heading-text patterns

## Strategic Principles
1. The content is the design — typography and spacing carry everything
2. Progress should feel visible and satisfying (sequential phases)
3. Reading comfort is the #1 priority (long-form content, code blocks)
4. Mobile should not feel like an afterthought
