Project Overview

Build a bare-bones HTTP/1.1 server using only Python's socket library. No frameworks, no web libraries. Your server should parse raw HTTP requests, route them to handlers, and return proper responses. This is the foundation everything else sits on. You'll understand exactly what happens when a browser sends a request. Implement threading to handle concurrent connections. Add support for serving static files. This project removes all magic from web development.

+---------+     TCP Connection      +------------------+
| Browser |  ------------------->   |  HTTP Server     |
| (curl)  |  <-------------------   |  (socket + TCP)  |
+---------+     HTTP Response       |                  |
                                     |  parse_request() |
                                     |  route()        |
                                     |  handle_*()     |
                                     +------------------+
                                               |
                                        +------+------+
                                        |  Handlers   |
                                        +-------------+
📄

Project Specification

  • Bind to a port and accept TCP connections
  • Parse the raw HTTP request line (method, path, version)
  • Parse HTTP headers into a dict
  • Route requests to handler functions based on HTTP method + path
  • Return properly formatted HTTP responses with status line, headers, body
  • Handle GET /, POST /data, 404 for unknown routes
  • Support concurrent connections via threading
  • Serve static files from a /static directory
  • Return proper Content-Type and Content-Length headers
📖

What to Read Before Starting

  • TCP/IP fundamentals: 3-way handshake, ports, sockets (read "Beej's Guide to Network Programming")
  • HTTP/1.1 message format: request line, headers, empty line, body (read RFC 7230 sections 2-4)
  • HTTP methods: GET, POST, PUT, DELETE, PATCH and their semantics
  • HTTP status codes: 1xx, 2xx, 3xx, 4xx, 5xx classes
  • Python socket module: bind(), listen(), accept(), send(), recv()
  • Threading vs async: when to use threads for I/O-bound work
🚀

What You'll Learn

  • Socket programming and the TCP server lifecycle (bind-listen-accept loop)
  • Parsing raw byte streams into structured HTTP messages
  • Writing a URL router from scratch using regex or string matching
  • Thread-based concurrency for handling multiple clients
  • HTTP header formatting and response construction
  • Debugging network protocols with curl -v and telnet
🔧

Implementation Steps

  1. Set up a TCP server socket, bind to localhost:8080, listen for connections
  2. Accept connections in a loop, receive data, print raw bytes to understand the format
  3. Parse the request line (split on spaces to get method, path, version)
  4. Parse headers (split on \r\n, split each line on first ': ')
  5. Build a Router class that stores (method, path) -> handler mappings
  6. Write handlers that return proper HTTP responses with status line + headers + body
  7. Add threading so each connection runs in its own thread
  8. Add static file serving (read files from disk, set Content-Type based on extension)
  9. Add error handling for malformed requests (return 400)
  10. Test with curl -v, browser, and ab (Apache Bench) for concurrency
✓

Verification Goals

  • curl -v http://localhost:8080/ returns a complete HTTP response with status line, headers, body
  • Server handles GET /, POST /data, and returns 404 for unknown routes
  • Opening 3 browser tabs simultaneously all load the page (concurrent connections work)
  • Server returns correct Content-Type for .html, .css, .js, .png files
  • Sending a malformed request returns 400 Bad Request
  • Server responds within 100ms for basic requests under light load
