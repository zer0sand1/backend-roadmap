Project Overview

Containerize all services (FastAPI, Celery, Redis, PostgreSQL, RabbitMQ, Express/TypeScript server) with Docker. Orchestrate with docker-compose. Add Nginx reverse proxy. Set up GitHub Actions CI/CD pipeline that runs lint/tests and builds/pushes images. Deploy the entire stack to Render or Fly.io with a real URL. This is the productionization layer - turning your projects into real, accessible services.

Project Specification

  • Multi-stage Dockerfiles for Python (FastAPI) and Node (Express/GraphQL)
  • Docker Compose with all services: app, worker, postgres, redis, rabbitmq, nginx
  • Health checks for all dependent services
  • Named volumes for persistent data (PostgreSQL, Redis, uploaded files)
  • Nginx reverse proxy routing: /api -> FastAPI, /graphql -> Apollo, / -> static
  • .dockerignore for faster builds
  • GitHub Actions CI: lint (ruff/black, eslint), test (pytest, vitest), build images
  • GitHub Actions CD: deploy to Render/Fly.io on main branch push
  • Environment variable management (.env, GitHub secrets)
  • Zero-downtime deploys (multiple replicas)
📖

What to Read Before Starting

  • Dockerfile best practices: multi-stage builds, layer caching, .dockerignore (read Docker docs)
  • Docker Compose: services, volumes, networks, depends_on, healthcheck
  • Docker networking: bridge network, port mapping, container DNS
  • Nginx configuration: upstream, location blocks, reverse proxy, rate limiting
  • CI/CD pipeline design: lint, test, build, push, deploy (read GitHub Actions docs)
  • Cloud platforms: Render vs Fly.io vs Railway vs AWS - trade-offs
  • Environment-based configuration: 12-factor app principles

Implementation Steps

  1. Write Dockerfile for FastAPI app (multi-stage: builder, runner)
  2. Write Dockerfile for TypeScript/Node app
  3. Write Docker Compose with all services and healthchecks
  4. Configure Nginx reverse proxy with location routing
  5. Add named volumes for PostgreSQL, Redis, uploaded files
  6. Create .dockerignore files
  7. Set up GitHub Actions workflow (lint -> test -> build -> push)
  8. Add Docker layer caching to CI for faster builds
  9. Deploy to Render or Fly.io (create account, link Docker image)
  10. Add production URL to README
✓

Verification Goals

  • docker-compose up --build starts all 8+ services; docker-compose ps shows them healthy
  • Nginx serves the API at /api and GraphQL at /graphql
  • curl http://localhost/api/health returns 200 from inside the container network
  • GitHub Actions: push to main triggers pipeline; lint + tests pass; images built
  • Pulling a fresh clone and running docker-compose up boots the entire stack
  • Deployed URL (https://your-app.onrender.com) is publicly accessible
  • docker-compose down --volumes cleans everything without errors
