Project Overview

Build a GraphQL API that wraps the URL shortener REST API (or uses the Prisma database directly). Implement a GraphQL schema with queries, mutations, and subscriptions (realtime events). Use DataLoader to solve the N+1 problem. Compare performance with the REST version. This project gives you the third API paradigm (after REST and gRPC) and teaches you schema-first API design.

Project Specification

  • Queries: urls, url(id), users, user(id), searchUrls(query, limit, offset)
  • Mutations: createUrl, updateUrl, deleteUrl, createUser, login
  • Subscriptions: urlClicked(urlId) - real-time notification when URL is accessed
  • Code-first schema with TypeGraphQL (decorator-based)
  • DataLoader for batching DB queries (solve N+1)
  • Input types for mutations with validation
  • Pagination with connection pattern (edges, nodes, pageInfo)
  • Authentication middleware (extract JWT, inject user into context)
  • Field-level authorization (admin-only fields)
📖

What to Read Before Starting

  • GraphQL type system: Schema, Query, Mutation, Subscription, ObjectType, InputType
  • Resolvers: how resolver chain works, root, args, context, info
  • N+1 problem: why GraphQL makes it worse, DataLoader batching + caching
  • Code-first vs SDL-first approach
  • GraphQL subscriptions over WebSocket
  • GraphQL vs REST: flexibility vs overfetching, caching, versioning
  • Apollo Server 4 + TypeGraphQL integration
🚀

What You'll Learn

  • TypeGraphQL decorators: @ObjectType, @Arg, @Query, @Mutation, @Subscription
  • DataLoader implementation: batch function, per-request caching
  • GraphQL context for auth user and shared state
  • Subscription resolver with pub/sub (in-memory or Redis)
  • Input types with validation decorators
  • Field resolvers for computed properties
  • Apollo Studio / GraphiQL for interactive querying
🔧

Implementation Steps

  1. Set up Apollo Server with TypeScript + TypeGraphQL
  2. Define GraphQL object types (Url, User, Click) with decorators
  3. Implement Query resolvers (urls, url, users)
  4. Implement Mutation resolvers (createUrl, login)
  5. Add authentication middleware (JWT -> context.user)
  6. Implement DataLoader for user -> urls batching
  7. Add pagination with connection type
  8. Implement Subscription resolver (urlClicked)
  9. Add Redis pub/sub for cross-instance subscriptions
  10. Benchmark: same query in GraphQL vs REST, compare response size and time
✓

Verification Goals

  • GraphiQL at /graphql shows schema documentation
  • Query `urls { id longUrl clicks { timestamp } }` returns nested data without N+1 (check console/sql log for 1 query not N+1)
  • createUrl mutation creates URL and returns it
  • urlClicked subscription fires when URL is visited (open GraphiQL in 2 tabs)
  • DataLoader batches 10 URL lookups into 1 query
  • GraphQL query returns less data than equivalent REST call for the same result
  • Auth middleware rejects unauthenticated queries
