RESTful Library Management API

Your first real framework - FastAPI with in-memory storage
PythonFastAPIPydanticUvicorn
🛠

Project Overview

Build a library management API (books, authors, members) using FastAPI. Temporarily store data in-memory (a Python dict). Focus on clean RESTful design, request validation with Pydantic, and automatic OpenAPI documentation. You'll feel the power of a framework after building from scratch in P01. Learn resource naming conventions, proper use of HTTP methods and status codes, dependency injection, and error handling patterns.

+--------+   HTTP   +-----------+   Pydantic    +-------------+
| Client | -------> |  FastAPI  |  validation   |  In-Memory  |
| (curl) | <------- |  Routers  |  -----------> |  Storage    |
+--------+   JSON   +-----------+               |  (dict)     |
                    |  /docs    |               +-------------+

                    +-----------+
📄

Project Specification

  • CRUD for books: GET /books, POST /books, GET /books/{id}, PUT /books/{id}, DELETE /books/{id}
  • CRUD for authors with book relationships
  • CRUD for members with book checkout tracking
  • Request validation using Pydantic (required fields, types, string lengths)
  • Proper HTTP status codes (200, 201, 204, 400, 404, 422)
  • Search books by title/author via query parameters
  • Pagination support (limit/offset parameters)
  • Error handling with consistent error response format
📖

What to Read Before Starting

  • REST architectural constraints: stateless, uniform interface, resource-based (read Fielding's dissertation chapter 5)
  • Resource naming best practices: plural nouns, nested resources, versioning (/v1/books)
  • HTTP methods and their idempotency guarantees
  • Pydantic models: Field types, validators, nested models
  • FastAPI dependency injection: how and why
  • OpenAPI / Swagger: auto-generated documentation
🚀

What You'll Learn

  • FastAPI project structure (routers, models, schemas, dependencies)
  • Pydantic for request/response validation and serialization
  • Path parameters, query parameters, and request body handling
  • HTTPException for structured error responses
  • Dependency injection for reusable logic (pagination, DB session)
  • Automatic OpenAPI docs generation at /docs
🔧

Implementation Steps

  1. Set up FastAPI project with main.py, routers/, schemas/, models/
  2. Define Pydantic schemas for Book, Author, Member (request/response variants)
  3. Create an in-memory "database" using dicts with auto-incrementing IDs
  4. Implement book CRUD endpoints with proper status codes
  5. Implement author CRUD endpoints with book relationship
  6. Add search endpoint with query parameter filtering
  7. Add pagination dependency for list endpoints
  8. Implement member checkout/return book endpoints
  9. Add error handling middleware for consistent error JSON
  10. Test all endpoints via Swagger UI and curl
✓

Verification Goals

  • GET /books returns all books; POST /books creates one with validation
  • PUT /books/{id} updates and returns the updated book
  • Pydantic rejects invalid data (missing fields, wrong types) with 422 + clear error
  • /docs shows interactive Swagger UI with all endpoints documented
  • GET /books?author=Tolkien returns filtered results
  • GET /books?limit=5&offset=10 returns paginated results
