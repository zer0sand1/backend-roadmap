🛠 Project Overview

Build a webhook system on top of the URL shortener. When a URL is accessed, fire a webhook to the registered callback URL. Implement reliable delivery with retry + backoff, payload signing (HMAC-SHA256), idempotency via event IDs, and a webhook dashboard for managing subscriptions. This is how modern APIs notify external systems of events.

                           For each subscriber:
                           1. Load subscription (url, secret)
                           2. Sign payload with HMAC-SHA256

                           5. On failure -> retry with backoff
                           6. Max retries -> mark failed

📄 Project Specification

  • POST /webhooks/register creates webhook subscription (url, events[], secret)
  • GET /webhooks lists subscriptions with status
  • PUT /webhooks/{id} updates subscription
  • DELETE /webhooks/{id} removes subscription
  • Events emitted on: url.created, url.accessed, url.deleted
  • Each webhook delivery attempt logged (status, response, duration)
  • HMAC-SHA256 signature in X-Webhook-Signature header
  • Retry: 5 attempts with exponential backoff (10s, 30s, 90s, 270s, 810s)
  • Event dedup by event_id (subscriber receives each event exactly once)
  • Webhook history: last 100 delivery attempts per subscription
  • Secret rotation endpoint

🔧 Implementation Steps

  1. Add WebhookSubscription model (url, events, secret, is_active)
  2. Add WebhookAttempt model (subscription_id, event_id, status, response, duration)
  3. Build webhook CRUD endpoints
  4. Create EventBus class that emits events to RabbitMQ
  5. Emit events on URL create/access/delete
  6. Build WebhookDispatcher worker (consume events -> deliver to subscribers)
  7. Implement HMAC-SHA256 signing of webhook payloads
  8. Implement retry with exponential backoff
  9. Add idempotency (track event_ids per subscriber)
  10. Build webhook delivery history API
  11. Create a simple webhook receiver (TypeScript/Express server) for testing

✓ Verification Goals

  • Creating a URL emits url.created event; subscriber receives webhook
  • Webhook payload includes X-Webhook-Signature header; receiver can verify it
  • Failing receiver causes retry; after 5 failures, subscription is marked as failing
  • Same event delivered at most once per subscriber (idempotency)
  • GET /webhooks/{id}/attempts shows delivery history with status codes
  • Secret rotation invalidates old signatures, new calls use new secret
  • Receiver written in TypeScript can verify HMAC and process events
