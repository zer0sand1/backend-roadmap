Project Overview

Build a gRPC-based user service that the URL shortener and other services can call. Define .proto files with services and messages. Implement both unary RPCs and server-side streaming. Learn how gRPC compares to REST - type safety, HTTP/2 multiplexing, binary encoding, and code generation. This is how modern microservices talk to each other internally.

+----------------+    gRPC (HTTP/2)    +----------------+
| URL Shortener   |   protobuf binary   |  User Service  |
| (gRPC client)   |  ---------------->  |  (gRPC server) |
+----------------+                     |                |
  GetUser(ids)       <----------------  |  port 50051    |
  CreateUser(data)                       +----------------+
  StreamActiveUsers()                           |

📄

Project Specification

  • Define UserService proto with: GetUser, CreateUser, UpdateUser, ListUsers, StreamActiveUsers
  • Unary RPCs: GetUser, CreateUser, UpdateUser - request/response pattern
  • Server-side streaming: StreamActiveUsers - client receives a stream of active users
  • Client-side streaming: BatchCreateUsers - client sends a stream of users, server responds once
  • Bidirectional streaming: ChatWithSupport - both sides stream messages
  • Inter-service auth: each gRPC call includes a service API key in metadata
  • Error handling: proper gRPC status codes (NOT_FOUND, ALREADY_EXISTS, INVALID_ARGUMENT)
  • Health check: gRPC health checking protocol
  • Reflection: gRPC reflection for debugging with grpcurl
📖

What to Read Before Starting

  • Protocol Buffers: message definition, field types, field numbers, package (read protobuf docs)
  • gRPC concepts: service definition, RPC types, stubs, server implementations (read gRPC docs)
  • HTTP/2 multiplexing: how gRPC reuses a single TCP connection for multiple streams
  • Binary encoding vs JSON: size and speed comparison
  • gRPC vs REST vs GraphQL: when to use each
  • gRPC error handling: status codes, error details, interceptor pattern
🚀

What You'll Learn

  • Writing .proto files with services and messages
  • Generating Python code from .proto with protoc/grpc_tools
  • Implementing gRPC server with Python (grpcio)
  • Implementing gRPC client with generated stubs
  • Server-side, client-side, and bidirectional streaming
  • gRPC interceptors for logging, auth, and error handling
  • Running gRPC services alongside FastAPI (different port)
🔧

Implementation Steps

  1. Define user.proto with UserService and messages
  2. Generate Python code with grpcio-tools (python -m grpc_tools.protoc ...)
  3. Implement gRPC server with UserService servicer
  4. Add SQLAlchemy integration to store users
  5. Implement all unary RPCs (GetUser, CreateUser, etc.)
  6. Add server-side streaming (StreamActiveUsers)
  7. Add client-side streaming (BatchCreateUsers)
  8. Add gRPC interceptor for authentication (check API key in metadata)
  9. Create FastAPI endpoint that calls gRPC service internally
  10. Test with grpcurl and write client tests
✓

Verification Goals

  • gRPC server starts on port 50051 and responds to GetUser requests
  • grpcurl list shows all defined services and methods
  • Server-side streaming sends active user updates every 5 seconds
  • Client-side streaming creates 100 users in a single RPC
  • gRPC call with invalid API key returns PermissionDenied error
  • FastAPI endpoint can call gRPC service and return results as JSON
  • Response size is significantly smaller than equivalent JSON (measure with protobuf vs json)
