Project Overview

Build a standalone job worker system. Producers publish jobs (send email, generate report) to RabbitMQ exchanges/queues. Workers consume, process, and ack/nack messages. Implement retry with exponential backoff, dead letter queues for failed jobs, and a job dashboard API. This is the backbone of reliable async processing.

Project Specification

  • POST /jobs enqueues a new job (type: email, report, cleanup; params: {...})
  • GET /jobs returns all jobs with status (queued, running, completed, failed)
  • GET /jobs/{id} returns job details and result
  • RabbitMQ setup: direct exchange per job type, competing consumers
  • Manual acknowledgment (basic_ack on success, basic_nack on failure)
  • Retry with exponential backoff (1s, 4s, 16s, 64s - max 4 retries)
  • Dead letter queue for jobs that exhaust retries
  • Idempotent job processing (dedup by job_id)
  • Graceful worker shutdown (prefetch, finish in-flight, then stop)
  • Job timeout (kill if running > 5 minutes)

🔧

Implementation Steps

  1. Start RabbitMQ with Docker
  2. Set up Pika connection with connection recovery
  3. Define exchanges (jobs) and queues (email_queue, report_queue)
  4. Implement job producer (POST /jobs -> publish to exchange)
  5. Implement worker (consume -> process -> ack/nack)
  6. Add retry logic with DLX + TTL for delayed retry
  7. Add job timeout (message TTL + dead letter)
  8. Add job status persistence (PostgreSQL)
  9. Build job dashboard API (list jobs, retry failed)
  10. Run multiple workers and test competing consumers
✓

Verification Goals

  • Job published to RabbitMQ survives worker restart (persistent messages)
  • Failed job retries 4 times with exponential backoff, then moves to DLQ
  • Multiple workers distribute jobs (competing consumers pattern)
  • GET /jobs shows correct status for each job
  • Manually nacking a message re-queues it for retry
  • DLQ contains jobs that exhausted retries (inspect via RabbitMQ Management UI)
  • Workers shut down gracefully (finish current job, don't lose queued jobs)
