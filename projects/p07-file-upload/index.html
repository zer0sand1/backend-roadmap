File Upload Service with Async Processing

Multipart uploads, image processing, task queues, CDN simulation
PythonFastAPICeleryRedisPillow

🛠 Project Overview

Build a service that accepts file uploads, validates them (type, size), processes them asynchronously (generate thumbnails), and stores them with a content-addressable scheme. Use Celery + Redis for background tasks. Simulate a CDN by serving files from a separate port/domain. This project teaches async task queues, file handling patterns, caching, and separation of concerns.

Client --> POST /upload --> FastAPI --> Celery Producer --> Redis Broker
                                   |                         |
                                   v                         v
                              File saved              Celery Worker
                              to disk/                    |
                              S3-like              resize_image()
                              storage              generate_thumbnails()
                                                         |
                                                   CDN Server
                                                   (separate port)

📄 Project Specification

  • POST /upload accepts multipart file with validation (max 50MB, allowed types: jpg/png/pdf)
  • POST /upload returns task_id immediately (async processing)
  • GET /task/{task_id} returns status (pending, processing, completed, failed)
  • Image uploads auto-generate 3 thumbnail sizes (150x150, 300x300, 800x800)
  • Files stored as content_hash.ext (dedup by SHA-256)
  • CDN server on port 8001 serves processed files
  • GET /cdn/{filename} returns cached file with Cache-Control headers
  • File type detection by magic bytes (not extension)
  • Virus scanning placeholder (simulated check in worker)

📖 What to Read Before Starting

  • Multipart/form-data encoding and streaming file uploads
  • Celery architecture: broker (Redis/RabbitMQ), worker, result backend
  • Content-addressable storage: content hash as unique identifier, deduplication
  • Image processing: Pillow for resize, thumbnail, format conversion
  • CDN concepts: origin server, edge cache, cache headers (Cache-Control, ETag)
  • Task queue vs message queue: differences and use cases

🚀 What You'll Learn

  • FastAPI UploadFile and streaming file handling (avoid loading into memory)
  • Celery task definition, configuration, and worker execution
  • Image processing pipeline with Pillow (resize, thumbnail, quality)
  • Content-addressable file storage with SHA-256 hashing
  • CDN simulation: separate server, caching headers, origin pull
  • Task status tracking with Celery result backend

🔧 Implementation Steps

  1. Install Celery + Redis, configure Celery app in FastAPI
  2. Create FileUpload endpoint with size/type validation
  3. Define Celery task for processing (validate_image -> generate_thumbnails -> store)
  4. Implement content-addressable storage (hash file, store as hex.ext)
  5. Create thumbnail sizes using Pillow
  6. Build task status endpoint (GET /task/{task_id})
  7. Create CDN server on port 8001 (separate FastAPI app or static file server)
  8. Add Cache-Control headers to CDN responses
  9. Handle cleanup of failed uploads (stale files)
  10. Test with curl -F "file=@photo.jpg" and verify thumbnails

✓ Verification Goals

  • Upload a 10MB file — it returns immediately and processes in background
  • Three thumbnail sizes exist after processing completes
  • Uploading the same file twice stores only one copy (dedup by hash)
  • Celery worker runs as a separate process (celery -A tasks worker --loglevel=info)
  • GET /cdn/thumb-150x150-{hash}.jpg returns the resized image
  • CDN response includes Cache-Control: public, max-age=3600 header
  • Invalid file type (e.g. .exe) returns 400 before any processing
