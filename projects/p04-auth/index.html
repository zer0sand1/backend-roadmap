Project Overview

Add user registration and login to the URL shortener. Implement JWT access + refresh tokens. Add role-based access control (admin vs regular user). Learn password hashing (bcrypt), token storage best practices, middleware for authentication, and OAuth2 flows. Users own their short URLs - only they can edit/delete them. Admins can manage all users. This is the security foundation every real API needs.

Project Specification

  • POST /register creates user with email + password (hashed with bcrypt)
  • POST /login validates credentials, returns access_token + refresh_token
  • Access tokens expire in 15 minutes, refresh tokens in 7 days
  • POST /refresh accepts refresh token, returns new access token
  • GET /me returns authenticated user's profile
  • POST /shorten creates URL owned by authenticated user
  • Only the owner can PUT/DELETE their URLs
  • Admin users can list all users and deactivate accounts
  • Rate limit login attempts (5 per minute per IP)
📖

What to Read Before Starting

  • Password hashing: bcrypt vs argon2, salt, work factor (read "How to Safely Store a Password")
  • JWT structure: header (alg), payload (claims), signature (HMAC or RSA)
  • Access tokens vs refresh tokens: why both are needed
  • OAuth2 flows: authorization code, implicit, client credentials (read RFC 6749)
  • Common web vulnerabilities: CSRF, XSS, SQL injection, timing attacks
  • FastAPI dependencies: how Depends() works for auth middleware
🚀

What You'll Learn

  • User registration flow with hashed password storage
  • JWT creation (python-jose / PyJWT), verification, and refresh logic
  • Password hashing with passlib + bcrypt
  • FastAPI dependency injection for reusable auth middleware
  • Role-based access control (RBAC) with enum roles
  • Refresh token rotation and revocation
🔧

Implementation Steps

  1. Add User model (id, email, hashed_password, role, is_active, created_at)
  2. Implement password hashing with bcrypt (passlib)
  3. Create POST /register endpoint with email validation
  4. Create POST /login endpoint, generate JWT access + refresh tokens
  5. Build auth middleware (Depends(get_current_user)) that validates Bearer token
  6. Add refresh token endpoint with rotation
  7. Associate URLs with users (add user_id foreign key)
  8. Implement RBAC - admin role with user management endpoints
  9. Add login rate limiting with Redis
  10. Test auth flow: register -> login -> access protected routes -> refresh
✓

Verification Goals

  • POST /register creates user; POST /login returns access_token and refresh_token
  • Accessing /me without token returns 401
  • Request with expired token returns 401
  • POST /refresh with valid refresh token returns new access_token
  • User A cannot DELETE User B's URL (returns 403)
  • Admin can GET /admin/users and see all users
  • Passwords in DB are bcrypt hashes (never plaintext)
