Project Overview

Write comprehensive tests for the URL shortener and order service. Unit tests, integration tests with a real test database, API tests with TestClient, mocking external services. Use pytest fixtures for clean test setup, factory_boy for test data generation, and Testcontainers for spinning up PostgreSQL in tests. This project is what separates professional engineers from hobbyists.

tests/
  unit/
    test_models.py        # Test model validation
    test_services.py      # Test business logic with mocks
  integration/
    test_database.py      # Test with real PostgreSQL (Testcontainers)
    test_repositories.py  # Test DB queries
  api/
    test_urls.py          # Test API endpoints (FastAPI TestClient)
    test_auth.py          # Test auth flow end-to-end
    test_orders.py        # Test order concurrency
  conftest.py             # Shared fixtures
  factories.py            # Factory boy models
📄

Project Specification

  • Unit tests for all Pydantic schemas (validation, edge cases)
  • Unit tests for business logic (URL shortening algorithm, auth helpers)
  • Integration tests for database models and queries
  • API tests for every endpoint (happy path + error cases)
  • Test database isolation (each test gets fresh tables)
  • Mock external services (payment gateway, email sender)
  • Factory boy for generating test data
  • Coverage report (aim for >85%)
  • Test for concurrent access patterns (P08 style)
📖

What to Read Before Starting

  • pytest architecture: fixtures, conftest.py, markers, parametrize
  • Mocking: pytest-mock, unittest.mock, when to mock vs not
  • Integration testing: why test with a real database
  • Testcontainers: programmatic Docker containers for testing
  • Factory boy: declarative test data generation
  • Coverage: pytest-cov, what to measure, what 100% coverage means
  • Test-driven development: red-green-refactor cycle
🚀

What You'll Learn

  • Writing clean pytest fixtures with proper scope (function, module, session)
  • FastAPI TestClient for async API testing
  • Testcontainers for PostgreSQL in tests (auto start/stop)
  • Factory boy for model factories with relationships
  • Mocking external HTTP calls with responses / httpx_mock
  • Parametrized tests for edge cases
  • Testing concurrent access (asyncio.gather with multiple requests)
  • Coverage configuration and reporting
🔧

Implementation Steps

  1. Set up pytest config (pyproject.toml or pytest.ini) with asyncio mode
  2. Create test factories with factory_boy for all models
  3. Write conftest.py with shared fixtures (test_client, test_db, auth_headers)
  4. Unit test Pydantic schemas (test validation, custom validators)
  5. Integration test database queries with Testcontainers
  6. API test all endpoints (200, 201, 400, 401, 403, 404, 409, 422, 429)
  7. Mock external services (payment gateway returning success/failure)
  8. Write concurrent access test for order service
  9. Add coverage measurement, set minimum threshold
  10. Document test patterns for future projects
✓

Verification Goals

  • pytest runs all tests and they pass
  • Tests use a real PostgreSQL database (via Testcontainers or test DB)
  • Factory boy generates valid test data
  • Mocked payment service returns configurable success/failure
  • Concurrent order test proves race conditions are handled
  • Coverage report shows >85% line coverage
  • Each test is independent (no shared state leaks between tests)
  • Running the full test suite takes <30 seconds
