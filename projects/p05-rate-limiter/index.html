Rate Limiter & API Gateway Middleware

Protect your API with Redis-based rate limiting and middleware
PythonFastAPIRedisASGI

🛠 Project Overview

Implement rate limiting on your URL shortener using Redis. Support both token bucket and sliding window algorithms. Build it as reusable ASGI middleware. Also add request logging, API key validation, and request transformation. These are the building blocks of an API gateway. Rate limiting is essential for production APIs — it prevents abuse, ensures fair usage, and protects backend resources.

📄 Project Specification

  • Implement sliding window rate limiter using Redis sorted sets
  • Implement token bucket rate limiter for comparison
  • Configurable rate limits per endpoint, per user, per IP
  • Rate limit headers: X-RateLimit-Limit, X-RateLimit-Remaining, X-RateLimit-Reset
  • Retry-After header when rate limited
  • Request logging middleware (method, path, status, duration, user_id)
  • API key authentication for service-to-service calls
  • Graceful degradation: fail-open vs fail-closed strategies

📖 What to Read Before Starting

  • Rate limiting algorithms: token bucket, sliding window, fixed window, leaky bucket (read "Rate Limiting Fundamentals" by Stripe)
  • Redis data types: STRING, SET, Sorted Set, Lua scripting for atomicity
  • ASGI specification: lifespan, scope, send/receive, middleware pattern
  • Rate limiting headers: IETF draft standard
  • Circuit breaker pattern and graceful degradation
  • Redis transactions: MULTI/EXEC vs Lua scripts for atomicity

🚀 What You'll Learn

  • Writing ASGI middleware using the call_next pattern
  • Redis sorted sets for sliding window counters (ZREMRANGEBYSCORE, ZCARD)
  • Token bucket algorithm implementation (refill rate, bucket capacity)
  • Lua scripting for atomic rate counter operations
  • Proper rate limit HTTP headers
  • Fail-open vs fail-closed: when to block vs when to allow

🔧 Implementation Steps

  1. Set up Redis connection pool in FastAPI
  2. Implement SlidingWindowRateLimiter class using Redis sorted sets
  3. Implement TokenBucketRateLimiter class for comparison
  4. Build ASGI middleware that checks rate before passing to router
  5. Add configurable limits: per-IP (100/min), per-user (1000/min), per-endpoint
  6. Add rate limit headers to response
  7. Implement API key authentication middleware
  8. Add request logging middleware (JSON structured log)
  9. Add graceful degradation (circuit breaker for Redis)
  10. Benchmark both algorithms and compare performance

✓ Verification Goals

  • After N requests in T seconds, API returns 429 Too Many Requests with Retry-After
  • Rate limit resets after the window expires (wait and retry succeeds)
  • Different users have independent rate limits (User A blocked, User B allowed)
  • Rate limit headers present on every response
  • With Redis down, server continues in "fail-open" mode (or "fail-closed" configurable)
  • Lua script performs window check + increment in a single atomic operation
  • Sliding window and token bucket both work correctly — testable via /limiter-test endpoint
