Project Overview

Build a caching layer for the URL shortener and file service. Implement multiple cache strategies: cache-aside, write-through, write-behind. Build an LRU cache from scratch. Add Redis-based distributed caching with TTL. Implement cache invalidation on data updates. Simulate a CDN edge cache with origin pull and stale-while-revalidate patterns.

Project Specification

  • LRU cache implementation from scratch (doubly linked list + hashmap)
  • Cache-aside pattern: read from cache first, on miss read DB + populate cache
  • Write-through: write to DB + cache atomically on updates
  • Write-behind: write to cache, async flush to DB
  • Redis-based distributed cache with JSON serialization
  • TTL support per cache entry (configurable per endpoint)
  • Cache invalidation on data mutation (webhook-based or event-driven)
  • Thundering herd prevention (mutex-based: only first request hits DB)
  • Stale-while-revalidate: serve stale data, refresh in background
  • Cache statistics: hit rate, miss rate, eviction count, average latency
📖

What to Read Before Starting

  • Cache strategies: cache-aside, read-through, write-through, write-behind (read "AWS Caching Patterns" or "Database Caching with Redis")
  • Cache invalidation: TTL, event-driven, write-invalidate, write-update
  • LRU vs LFU vs FIFO eviction policies
  • Thundering herd problem: what happens when cache expires and 1000 requests hit DB
  • Stale-while-revalidate pattern (Cloudflare CDN approach)
  • Redis data structures for caching: SET with TTL, Hash for partial updates

What You'll Learn

  • Redis SET/GET with TTL for distributed caching

Implementation Steps

  1. Implement LRU cache class in Python (Node class, hashmap, doubly linked list)
  2. Test LRU correctness (insert, access, eviction order)
  3. Add Redis cache class with TTL support
  4. Add cache-aside decorator/middleware for FastAPI endpoints
  5. Add write-through invalidation (update DB -> invalidate cache)
  6. Add thundering herd prevention (distributed lock on cache miss)
  7. Implement stale-while-revalidate pattern
  8. Add cache statistics endpoint (GET /cache/stats)
  9. Integrate with URL shortener (cache redirect lookups)
  10. Benchmark: cache hit vs miss latency
✓

Verification Goals

  • Cache hit serves response in <5ms, cache miss + DB in <50ms (measurable)
  • LRU eviction removes least recently used entry when full
  • Updating a URL immediately invalidates its cache entry
  • 10 concurrent requests for a missing key - only 1 hits the database
  • TTL expiration automatically refreshes cache on next request
  • Stale-while-revalidate serves stale data within 60s TTL window
  • Cache hit ratio > 80% on repeated URL accesses
