Project Overview

Build a search service over the URL shortener's bookmarks or a set of documents. Implement full-text search using PostgreSQL's built-in FTS first, then optionally rewrite with Elasticsearch. Learn inverted indexes, tokenization, stemming, relevance scoring (TF-IDF, BM25), and typo-tolerant search with Levenshtein distance.

Project Specification

  • Index bookmarks/documents with title, description, content, tags
  • Full-text search across all fields with ranking
  • Search endpoint: GET /search?q=blue+shoes&page=1&limit=20
  • Type-ahead / autocomplete (return results after 2+ characters)
  • Fuzzy search for typos (Levenshtein distance, trigram similarity)
  • Search results include relevance score and highlighting
  • Filter by tags, date range, document type
  • Faceted search: count results by tag category
  • PostgreSQL FTS implementation first, then optional Elasticsearch
📖

What to Read Before Starting

  • Inverted index data structure (posting lists, term dictionary)
  • Tokenization, stemming, stop words, normalization (read "Introduction to Information Retrieval" Ch 1-2)
  • TF-IDF and BM25 ranking algorithms - how they work mathematically
  • PostgreSQL full-text search: tsvector, tsquery, ts_rank, GIN indexes
  • Trigrams for fuzzy matching (pg_trgm extension)
  • Levenshtein distance algorithm for typo tolerance
  • Elasticsearch query DSL (match, multi_match, bool, function_score)
🚀

What You'll Learn

  • PostgreSQL tsvector generation and tsquery matching
  • GIN indexes for full-text search performance
  • Search relevance tuning (field boosting, normalization)
  • Trigram-based fuzzy string matching
  • Type-ahead / autocomplete implementation (prefix matching)
  • Search result highlighting (ts_headline)
  • Elasticsearch indexing, mapping, and query DSL (optional stretch)
🔧

Implementation Steps

  1. Add search_vector tsvector column to documents table
  2. Create GIN index on search_vector
  3. Implement PostgreSQL FTS query with ts_rank ordering
  4. Add highlighting with ts_headline
  5. Implement type-ahead with prefix matching (or trigrams)
  6. Add fuzzy search using pg_trgm similarity
  7. Add faceted search (aggregations by tag)
  8. (Optional) Set up Elasticsearch, index documents, run same queries
  9. Compare PostgreSQL vs Elasticsearch performance
  10. Load test with 10K+ documents
✓

Verification Goals

  • Search "blue shoe" finds "blue suede shoes" (stemming works)
  • Relevant results appear before less relevant ones (check score ordering)
  • Typo "sho" suggests "shoe" (fuzzy match returns results)
  • Type-ahead returns results within 100ms after 2 keystrokes
  • Search latency under 200ms for 10K indexed documents
  • Highlighting shows matched terms in results
  • Filters (tag, date range) correctly narrow results
