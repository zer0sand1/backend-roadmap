URL Shortener with PostgreSQL

Persistence — first real database. SQLAlchemy, migrations, indexes
PythonFastAPIPostgreSQLSQLAlchemyAlembic

🛠 Project Overview

Build a URL shortener (like bit.ly). Store short_code to long_url mappings in PostgreSQL. Use SQLAlchemy as the ORM and Alembic for schema migrations. Learn connection pooling, database indexing, and the N+1 query problem. Add click tracking (count how many times each short URL is accessed). Implement Base62 encoding for short codes. This project teaches you everything about connecting a web app to a relational database.

+--------+  POST /shorten   +----------+  SQLAlchemy  +------------+
| Client |  GET /{code}     | FastAPI  |  ----------> | PostgreSQL |
+--------+  (302 redirect)  +----------+  Alembic     +------------+
                                  |                    |  urls      |
                            +-----+-----+             |  clicks    |
                            |  Redis     |             +------------+
                            |  (optional |
                            |   cache)   |
                            +-----------+

📄 Project Specification

  • POST /shorten accepts {url: "..."} and returns {short_code: "...", short_url: "..."}
  • GET /{short_code} redirects to the original URL (302 for analytics, 301 for permanent)
  • GET /{short_code}/stats returns click count and last accessed time
  • Custom short codes (optional alias) via POST /shorten {url: "...", custom_code: "..."}
  • Base62 encoded short codes (a-z, A-Z, 0-9) for compact URLs
  • Track each click with timestamp, user agent, referrer
  • Database indexes on short_code for fast lookups

📖 What to Read Before Starting

  • Relational database concepts: tables, primary keys, foreign keys, indexes (read "Use the Index, Luke")
  • SQL CRUD: SELECT, INSERT, UPDATE, DELETE with WHERE clauses
  • SQLAlchemy Core vs ORM: when to use each
  • Alembic migrations: autogenerate, upgrade, downgrade
  • Base62 encoding algorithm
  • Connection pooling: why it matters, how SQLAlchemy manages it
  • 301 vs 302 redirect: SEO and caching implications

🚀 What You'll Learn

  • SQLAlchemy model definitions with Column types, relationships, indexes
  • Writing and running Alembic migration scripts
  • Connection pooling configuration (pool_size, max_overflow)
  • Base62 encoding/decoding for short code generation
  • Redirect handling in FastAPI (RedirectResponse)
  • Click tracking with timestamp logging

🔧 Implementation Steps

  1. Install PostgreSQL, create database, configure SQLAlchemy connection string
  2. Define URL model (id, long_url, short_code, created_at, click_count)
  3. Set up Alembic, generate initial migration, apply it
  4. Implement Base62 encoder/decoder
  5. Create POST /shorten endpoint with URL validation (Pydantic HttpUrl)
  6. Create GET /{short_code} with 302 redirect
  7. Add click tracking model (id, url_id, timestamp, user_agent, referrer)
  8. Add GET /{short_code}/stats endpoint
  9. Add database index on short_code column
  10. Test with curl and verify database entries

✓ Verification Goals

  • POST /shorten returns {"short_code": "ab3X9", "short_url": "http://localhost:8000/ab3X9"}
  • Visiting the short URL redirects to the original URL
  • Database persists across server restarts (data survives)
  • Alembic can upgrade and downgrade schema without data loss
  • EXPLAIN ANALYZE shows an index scan (not sequential scan) for code lookups
  • GET /stats shows click_count > 0 after visiting the URL
