Project Overview

Add structured logging, Prometheus metrics, and OpenTelemetry tracing to your URL shortener. Ship logs to Elasticsearch and visualize in Kibana. Create a Grafana dashboard showing request rate, error rate, latency (p50/p95/p99), and cache hit ratio. Instrument a distributed trace across the webhook delivery flow. This makes your system observable - you can answer any question about what's happening.

Project Specification

  • Structured logging with request_id, service, endpoint, duration, user_id, status_code
  • Prometheus metrics: /metrics endpoint with request counter, latency histogram, in-flight gauge
  • RED metrics: Rate (requests/sec), Errors (error rate), Duration (latency distribution)
  • OpenTelemetry tracing: auto-instrument FastAPI, manual spans for critical paths
  • Trace context propagation across services (REST calls carry trace_id in headers)
  • Grafana dashboard: request rate panel, p50/p95/p99 latency, error rate, cache hit ratio
  • Alert rules: error rate > 5% for 5 minutes, p99 > 500ms
  • JSON logs shipped to Elasticsearch (Filebeat or direct HTTP)
  • Kibana dashboard for log search with structured fields
📖

What to Read Before Starting

  • Three pillars of observability: logs, metrics, traces - what each solves (read "Observability: A Manifesto")
  • Structured logging vs unstructured: JSON format, log levels, correlation IDs
  • Prometheus metric types: Counter (rate), Gauge (value), Histogram (distribution), Summary
  • OpenTelemetry: traces, spans, span context, propagation (read OTel docs)
  • RED method: Rate, Errors, Duration for service monitoring
  • Grafana: data sources, panels, dashboards, alerting rules
  • ELK stack: Elasticsearch for storage, Kibana for visualization

What You'll Learn

  • JSON structured logging with structlog library
  • Prometheus client instrumentation (prometheus_client) in FastAPI
  • Histogram buckets for latency measurement
  • OpenTelemetry auto-instrumentation + custom spans
  • Trace context propagation across HTTP calls (W3C traceparent header)
  • Grafana dashboard creation with PromQL queries
  • Shipping logs to Elasticsearch via HTTP API
🔧

Implementation Steps

  1. Add structlog for JSON structured logging
  2. Add request_id middleware (generate UUID per request, log it)
  3. Add Prometheus metrics middleware (request count, latency histogram)
  4. Expose /metrics endpoint with prometheus_client
  5. Set up OpenTelemetry with FastAPI auto-instrumentation
  6. Add manual spans for critical operations (DB queries, external calls)
  7. Propagate trace context across services (HTTP headers)
  8. Set up Prometheus to scrape /metrics (prometheus.yml)
  9. Set up Grafana, connect Prometheus data source, build dashboard
  10. Set up Jaeger/Zipkin for trace visualization
  11. Ship logs to Elasticsearch, create Kibana dashboard
✓

Verification Goals

  • /metrics endpoint returns Prometheus-formatted metrics
  • Logs contain request_id, duration_ms, status_code, service_name in JSON
  • Grafana dashboard shows live request rate, error rate, p95 latency
  • Single HTTP request creates a trace visible in Jaeger with all spans
  • Dashboard alert fires when error rate exceeds threshold
  • Kibana dashboard shows structured log fields (not just raw text)
  • p99 latency panel shows accurate distribution from histogram data
